## Urutan dan pembagian kerja

Sprint 1 menyelesaikan MVP P0. Sprint 2 memvalidasi nilai ilmiah dan operasional P1. Sprint 3 memuat riset dan perluasan P2 yang opsional. Durasi ditetapkan bersama saat planning; target alokasi setiap anggota adalah sepertiga kapasitas tim. Semua anggota mengerjakan kode.

Setiap file memuat task milik orang tersebut, spesifikasi, kriteria selesai, dependensi rekan, dan checklist sebelum PR. ID task lama dipertahankan untuk keterlacakan.

## Integrasi dan review bersama

- [ ] Awal sprint: sepakati estimasi, kontrak payload, dependency, dan satu reviewer lintas jalur untuk tiap task.
- [ ] Review bergilir agar setiap anggota meninjau kode di luar jalur utamanya.
- [ ] Integrasikan awal memakai fixture kontrak; ganti fixture hanya saat data nyata siap.
- [ ] Akhir sprint: demo output berjalan, cek exit criteria, catat blocker, dan perbarui status [`TASKS.md`](TASKS.md).
- [ ] Jangan memakai label “live”, “terharmonisasi”, “tervalidasi”, atau “siap operasional” tanpa bukti dan acceptance criteria.
